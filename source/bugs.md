- `database.rb`'s `.to_sym` calls assumed raw Ruby strings; broke on `Prog::String` (e.g. passed via `structure.name`). Fixed via `.to_str.to_sym`.
- `proxy_create_table`'s primary-key branch used `type_name.to_sym` instead of `member.name.to_sym`, hardcoding every primary-key column's name to `"Primary_Key"`.
- `Member#to_s` treated a real `false` value as "no value" (`if value`), so `done := false` displayed as `done: Bool` with no value.
- `!=` deriving from a declared `==` crashed against an incompatible right operand: `backend/string.code`/`member.code`/`struct.code`'s `==` all assumed `right` was already the same type. Fixed with `.?` safe navigation.
- `struct.code`/`member.code`'s own `@operator === @infix` could never run -- `===` is a built-in the interpreter always resolves first. Confirmed dead, both removed.
- `Any`'s wildcard treatment initially skipped `=>=`/`=<=`/`=/=`: `X === Any` was `true` but `X =>= Any` stayed `false`, contradicting "`===` is mutual `=>=`". All seven now share the same check.
- `Table#create`/`#update` handed values straight to Sequel, which can't literalize an `Prog::String` or a raw Symbol (treated as a column reference, not a string). New `#sql_literal_value` unwraps both.
- `build_instance_of_type` only set `.name`/`.types` via Ruby attrs, not `@declarations`; a composed type sharing a built-in's Ruby class (`Tasks | Table {}` -> `Prog::Table`) had `instance.name` stuck on the backing class's own name ("Table").
- Same bug in `#build_enum`: `Prog::Enum.new` (no name arg) baked "Instance" into `@declarations['name']`; a struct member typed with a user enum always displayed "Instance" instead of the real name.
- Lexer: `>` immediately followed by `,`/`;` (no space) lexed as one bogus operator token instead of two, breaking struct annotations followed by either. Added both to `ILLEGAL_OPERATOR_CHARS`.
- Re-declaring a bare named struct with the identical shape raised `Undeclared_Type_Structure` instead of being a no-op. Now allowed. Also made `Struct#structure_declaration_equal?` order-insensitive once every member is named (`<a: X, b: Y>` == `<b: Y, a: X>`); still positional when any member is unnamed.
- `Undeclared_Type_Structure`'s own error message crashed rendering a named member with no `: Type` annotation (`done := false`, `.type` nil). Falls back to rendering the default value.
- `Empty <>` interpreted as `Undeclared_Identifier` on `Empty` instead of an empty struct (`Empty <id: Int>` was fine). Fixed as a side effect of the self-referential-struct fix below -- a fresh bare named struct now predeclares an empty stand-in before its members run, and `#register_bare_named_struct`'s new stub branch fills it in even when there are zero members.
- A bare named struct whose own member's `: Type` annotation referenced the struct's own name (`Scope <enclosing_scope_reference: Scope>`, `Node <parent: Node>`) raised `Undeclared_Identifier` -- `#interp_struct` resolved every member's annotation before `#register_bare_named_struct` ever declared the name. Now `#predeclare_bare_named_struct_stub` declares an empty stand-in on the scope first (mirroring how a bare `Type` is declared before its own body runs), members resolve against it, and `#register_bare_named_struct` swaps the finished struct in -- `#repoint_struct_self_reference` repoints the self-referential slots at the real struct so `Node.types.get(1) == Node`. `Struct_Expr` is already hoisted by the forward-declaration machinery, so this also unblocks mutually-referential structs (`A <partner: B>` / `B <partner: A>`).
- `Name <>` then `Name <...full...>` (the empty-struct-as-forward-declaration idiom, used in `backend/scopes.code`) raised `Undeclared_Tagged_Type` -- it hit the deliberate "bare named struct can't be redeclared with a different shape" rule (`test_redeclaring_bare_named_struct_with_a_different_shape_still_raises`), which didn't distinguish an empty placeholder from a real prior shape. `#predeclare_bare_named_struct_stub` now treats an existing *empty* (`names.empty?`) struct under the name as the stand-in to fill in; two genuinely non-empty shapes still raise.
- `Prog::Range` was a `::Range` subclass, so a range value had none of the machinery every other built-in gets: `(1...5) === Range` was `false`, `(1...5).to_a()` / `.map(...)` / `.length()` / `.include?(3)` all raised `Undeclared_Identifier` (zero methods), and `x: Range = 1...5` raised `Type_Contract_Violation` ("got unknown") -- ranges could be `for`-looped and nothing else. Root cause: it was the one value type that wasn't `Instance` + Ruby class + `.code` file, so `#maybe_instance` / `#link_instance_to_type` / `#type_name_to_string` had no Range case and `Range {}` in preload was an empty shell. Rewrote it as a proxy class: `Prog::Range < Instance` wrapping a `::Range` in `@range` (`backend/proxies/range.rb`), a real `backend/range.code` API (`start`/`finish`/`excludes_end?`/`length`/`include?`/`min`/`max`/`sum`/`values`/`to_s` proxies + `each`/`map`/`filter`/`reduce`/`find`/`any?`/`all?` in Backend), `@load`ed by global. `#interp_range_infix` now builds `Prog::Range.new(::Range.new(from, to, exclude_end))` and links it; `#interp_for_loop` iterates `collection.range`. The old `has? -> false` stub is gone (a real Instance has a real `has?`).
- A struct with a member whose *name* collides with a reflective struct key (`types`, `names`, `type_names`, `values` — e.g. `Structure <types: Array\Any, names: Array\String>` in a `backend/expressions.code` AST-node port) crashed struct composition with `NoMethodError: undefined method '[]' for nil`. `Struct#type_objects` read `@declarations['types']`, which the `types:` member's own `declare` call had already overwritten with the member's value (nil), so `type_objects` returned nil and `#interp_struct_composition`'s `own.type_objects[i]` blew up. Fixed by holding the per-member data (`names`/`type_names`/`type_objects`/`values`) in plain Ruby ivars — parallel to how `@names`/`@type_names`/`@values` already were — so a member name shadowing the `.names`/`.types` *dot-access* can't corrupt the struct's own internal member table. Also improved `Undeclared_Tagged_Type`'s message for `Name <...>` where `Name` is an existing type (was "Enum tagged with '' is not declared"; now "Enum is already a declared type — ... needs a name that isn't taken").
